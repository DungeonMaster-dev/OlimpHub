# OlimpHub

**OlimpHub** — персональная платформа для системной подготовки к олимпиадам по программированию и математике. Она объединит единый каталог задач, персональный учебный трек, историю решений и расширяемые интеграции с внешними источниками.

> На текущем этапе репозиторий содержит архитектурную основу проекта. Реализация продуктовых модулей начинается после утверждения приоритетов первого релиза.

## Цель продукта

Платформа должна сокращать путь от найденной задачи до осмысленного обучения: помогать сохранить задачу из разных источников, понять её место в программе подготовки, решать её в удобном процессе и анализировать накопленный опыт. OlimpHub проектируется как личный продукт с качеством, достаточным для дальнейшего роста числа источников, образовательных сценариев и пользователей.

| Область | Что предоставляет OlimpHub |
|---|---|
| Каталог задач | Единая нормализованная карточка задачи вне зависимости от источника, темы и сложности. |
| Подготовка | Подборки, цели, тренировочные сессии, заметки, попытки решения и рефлексия. |
| Аналитика | Прозрачная статистика по темам, сложности, времени и пробелам в подготовке. |
| Интеграции | Подключаемые адаптеры источников задач без проникновения их форматов в доменную модель. |

## Архитектурный курс

OlimpHub начинается как **модульный монолит** с чёткими доменными границами. Такой подход даёт быстрый и надёжный путь к первому релизу, не препятствуя последующему выделению интеграций, поиска или аналитики в самостоятельные сервисы при реальной необходимости.

Подробное решение зафиксировано в [архитектурном документе](docs/architecture.md). Порядок реализации описан в [дорожной карте](docs/roadmap.md), а обязательные правила участия — в [CONTRIBUTING.md](CONTRIBUTING.md).

## Рабочие принципы

Код и изменения в репозитории должны соответствовать следующим принципам.

| Приоритет | Принцип |
|---:|---|
| 1 | Расширяемая архитектура и ясные границы модулей важнее локальной скорости разработки. |
| 2 | Каждый пользовательский сценарий должен быть понятным, быстрым и доступным с клавиатуры. |
| 3 | Производительность и наблюдаемость проектируются до появления нагрузки, а не после инцидента. |
| 4 | Данные пользователя, учётные данные интеграций и права доступа защищаются по умолчанию. |
| 5 | Бизнес-правила покрываются автоматическими тестами; критичные изменения проверяются до слияния. |
| 6 | Внешние источники задач подключаются только через стабильные контракты адаптеров. |

## Статус

Репозиторий инициализирован. Следующий этап — согласовать границы **MVP** по архитектурной дорожной карте и создать базовый каркас приложения, не начиная параллельную разработку несвязанных функций.
